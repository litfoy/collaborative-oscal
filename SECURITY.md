# Security Policy

## Supported versions

Collaborative OSCAL is currently in alpha development.
There is no long-term support policy yet; security fixes are handled on the
active default branch.

## Reporting a vulnerability

Please do not open public issues for undisclosed vulnerabilities.

Use GitHub's private vulnerability reporting for this repository:
- https://github.com/litfoy/collaborative-oscal/security/advisories/new

If private reporting is unavailable in your environment, open a minimal issue
without exploit details and request a private follow-up channel.

## What to include

Provide as much of the following as possible:
- affected component(s) and version/commit
- reproduction steps or proof-of-concept
- security impact and likely attack preconditions
- suggested remediation (if available)

## Response expectations

As an alpha project, response times are best effort.
Maintainers will triage reports, assess impact, and coordinate disclosure once
a fix or mitigation is available.

## Current alpha-stage security limitations

The project is experimental and not intended for production use with
confidential or regulated data. Review known limitations in `README.md` and
`docs/development.md` before deployment.
